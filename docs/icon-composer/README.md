# App icon variants

Dark is the default app icon in Debug and Release, including Finder and the
installed app. Debug uses the matching Dark icon with its D badge.
Classic uses the existing [AppIcon.icon](../../Resources/AppIcon.icon) document.
[Ice Blue](../../Resources/AppIconIce.icon) derives from that document. It keeps
the pane outlines, corner radii, canvas, layer order, positions, and scale.
It uses a pale ice background, blue left panes, and a mint-to-teal right pane.
Inset SVG gradient contours create the thicker glossy rims inside the original
outlines. Pane translucency and shadow strength are adjusted for these colors.
The traffic-light SVG remains an exact copy. Each Debug copy adds the existing D
badge. Ice Blue places that badge above its opaque panes so it stays visible.
[Dark](../../Resources/AppIconDark.icon) uses the same foreground as Ice Blue
with a dark background. It is a separate choice, independent of the app's
appearance setting, and has a matching Debug copy.

Open any `.icon` document in Apple's Icon Composer. When changing source
geometry, copy those changes into the other five documents. Keep appearance
changes aligned within each base/Debug pair. Edit the pane SVG gradients to
adjust the Ice rim colors; Icon Composer retains the native glass and shadow
effects. `appIconVariantsPreserveSourceGeometry` checks the outlines, canvas,
composition, and matching Debug copies.

Settings → General → Appearance has three buttons: Classic, Ice Blue, and Dark.
Each button contains its centered preview and name. A border and checkmark show
the selected choice. Tab moves between choices; Space or Return selects one.
Dark is the default. The local `BetterTileAppIcon` preference saves
the selection across launches. Missing and unknown values use Dark. Existing
Classic, Ice Blue, and Dark choices are preserved. Debug and Release
keep their existing separate preferences and Debug retains its D badge.

Show Dock icon sits directly above the picker. The picker updates Finder even
when the Dock icon is hidden. Showing the Dock icon reapplies the saved choice.
Selecting an icon does not change Dock visibility.

The picker loads icons from Xcode's compiled asset catalog. The public AppKit
`NSApplication.applicationIconImage` API changes the running app's Dock icon.
The public `NSWorkspace.setIcon(_:forFile:options:)` API sets a custom Finder
icon on the running app's bundle. Selecting Dark removes that custom icon and
restores the built-in icon in Finder and the Dock. Dock behavior follows
[Apple's documented Dock icon behavior](https://developer.apple.com/documentation/appkit/nsapplication/applicationiconimage).

An explicit or saved icon choice updates Finder. A fresh install leaves any
custom icon set outside BetterTile alone. Launch reapplies a saved choice,
including after an update replaces the app. Finder updates require a writable
app bundle. A failed write keeps the saved choice and Dock behavior; Settings
shows an error after a failed selection. BetterTile never requests elevated
access or edits the app's signed `Contents` directory.

### Finder metadata and signature checks

An isolated signed test app on macOS 27.0.1 confirmed that custom Finder icons
add an `Icon` file with a trailing carriage return and Finder metadata at the
bundle root. Ordinary `codesign --verify --deep` still passes, and every file
under `Contents` remains byte-for-byte unchanged. Strict verification rejects
the Finder metadata with "resource fork, Finder information, or similar
detritus not allowed" while a custom icon is active. Clearing the icon through
`NSWorkspace.setIcon(nil, ...)` restores strict verification. Removing only the
root Finder metadata also removes the effective custom icon, so it cannot
preserve both the custom icon and strict verification.

This is a runtime customization. Release packaging and its strict signature
checks remain unchanged. BetterTile does not re-sign itself, replace icon
resources, edit Info.plist, or change Sparkle's validation. Sparkle 2.9.5's
`SUCodeSigningVerifier` uses ordinary all-architecture signature validation;
its delta hash in `SUBinaryDeltaCommon` excludes custom-icon resource data.
These source checks do not substitute for a full signed update test.
Finder custom icons are static images generated by AppKit; they do not retain
Icon Composer's live glass layers.

No new dependency, permission, networking, private API, or window mutation is
introduced. The existing local icon preference and generated Finder icon data
stay on the Mac. See [the security disclosure](../../SECURITY.md#app-icon-customization).

## Verification

The Finder integration test uses a disposable ad-hoc-signed app. It verifies
the actual icon change, unchanged signed contents, ordinary signature
validation, the expected strict-verification rejection of custom Finder
metadata, and restoration of strict validation after selecting Dark:

```sh
BETTERTILE_TEST_FINDER_ICON=1 swift test \
  --filter finderIconChangesPreserveSignedContentsAndRestoreThePrimaryIcon
```

It never launches the probe app or changes an installed app. The test is opt-in
because it uses native icon services. Unit tests inject the Finder operation
to cover missing resources, failed writes, restoration, and invalid targets.

The earlier icon-picker validation below predates Finder customization:

- Debug and Release Xcode builds with `CODE_SIGNING_ALLOWED=NO`.
- Swift tests with `--scratch-path /tmp/bettertile-picker-tests`: preference
  restoration (including Dark), fallback, geometry, and matching Debug copies.
- All three compiled icon names load in Release and Debug.
- Native picker interaction in an isolated app using the actual picker source
  and compiled icon catalog: click, Tab, Space, Return, and Dock visibility.
- The reported unchanged Dock icon was reproduced with Show Dock icon off.
  The maintainer confirmed that the running app changed to Ice Blue when the
  toggle was turned on. No Dock rendering API change was required.
- Light and dark picker captures and Apple-rendered icon previews are in
  [previews](previews). Icon exports use Icon Composer's `ictool` for macOS.
  Unsuffixed icon exports use design generation 26; `*-27.png` exports use
  generation 27. The final Ice source was also opened and checked in Icon
  Composer. These are review images, not runtime PNG resources.
- Full-app relaunch, live system appearance changes, and VoiceOver traversal
  remain manual checks. These builds are unsigned and are not distributed.

# BetterTile 0.6.1 Beta

- **Layouts stay as you left them.** After sleep, lock, docking, undocking or
  a short display dropout, BetterTile no longer moves windows while macOS is
  still restoring displays and windows. It waits until they settle, for at
  most about 5 seconds after the wake, unlock or display change, and only then
  updates layouts. After wake, Adaptive also waits for its windows to
  come back, so a window that macOS reports late keeps its place. A Tabbed
  window that is minimized and restored while the Mac sleeps keeps its tab.
- **Desktops keep their modes when displays change.** When a display
  disconnects and comes back, or when you dock or undock, each desktop keeps
  its mode, panes, pane sizes and tab groups. The layout is fitted to the new
  screen. A new switch, **Keep desktop modes when displays change**, in
  Settings → Window Layout → Window mode, controls whether a desktop carries
  its mode and layout to another screen. It is on by default. When it is off,
  each screen remembers its own modes, from the next screen change.
- **Windows return to their own place.** A Tabbed window that you hide,
  minimize or put in full screen comes back to its own pane and tab position.
  If it was the selected tab, it is selected again. In Adaptive, the windows of
  a hidden app return to their own panes and sizes when you show the app again.
- **Saved Layouts.** Apply no longer sometimes refuses with "0 placed" and
  moves nothing. The menu bar Saved Layouts picker is larger and shows the
  icon of each pane's preferred app; App Group panes show the group symbol.
  If a display change interrupts an Automatic Apply before it places any
  window, BetterTile tries that Apply once more after the displays settle.
- **Tabbed.**
  - A pane's **+** request for an app now works right after that app quit.
  - Selecting a tab, restoring focus and **+** requests no longer fail with
    "The application could not be activated" or "The application is no longer
    running" when macOS briefly fails to identify a running app.
  - With Auto-hide on, a revealed tab bar now stays above its pane's window,
    so tab clicks reach it.
  - A new **Place windows** choice in Settings → Window Layout → Tabbed sets
    how windows fill the starting layout: **All in one pane** (the default),
    **One per pane**, or **Keep Adaptive panes**. Entering Tabbed from Adaptive
    now uses the starting layout. Choose **Keep Adaptive panes** to keep the
    Adaptive arrangement, as before.
- **Adaptive.**
  - The other windows fill the space when a window closes or leaves the
    desktop, also when the app keeps the closed window open off screen, or
    when the window closes just as you switch desktops.
  - Focus mode Restore no longer leaves a window at full height over its
    neighbor. A window that opens while Restore waits is placed in the layout.
  - Apps that stop responding no longer slow down every layout update.
    BetterTile asks them less often until they respond again.
- **Snapping and resizing.**
  - A window drag that carries the window to another desktop keeps snapping
    there: the snap preview shows on the new desktop, and release snaps the
    window.
  - The snap preview now shows when the pointer rests, also when macOS reports
    the window's movement late.
  - Linked neighbors follow a fast edge resize from its first movement more
    reliably.
  - Restore no longer moves a window to a place that no connected display can
    show. The window stays where it is, and Restore works again after the
    display reconnects.
- **Show overlays in screen recordings.** A new switch in Settings → General
  lets screenshots and screen recordings show the Layout Wheel, snap and layout
  previews, and drop cues. It is off by default. Tab bars, dividers and
  messages always show.
- **Reliability and memory.** Peak memory is lower when an Auto-hide tab bar
  first appears, and when Settings opens the Layout Wheel and Menu Bar pages.
  Records of closed windows, quit apps, and displays and desktops that are
  gone no longer grow with long uptime. BetterTile keeps what a returning
  display or desktop still needs.

BetterTile still runs only on Apple silicon Macs and requires macOS 26.

A second **+** request for an app that is still running is refused for up to
30 seconds after the earlier request. After you take a window to another
desktop and come back, the other Adaptive windows fill its space about 2
seconds later. While displays change, and after wake or unlock, new and closed
windows wait up to about 5 seconds for the layout to update. If you move a
floating Tabbed window to another desktop, each return from sleep, lock or the
screen saver waits the full 5 seconds until that window comes back or closes;
the layout does not change. If you change only the macOS icon style, the menu
bar Saved Layouts picker can show the old icons until BetterTile restarts.
Capture tools can differ in how they honor **Show overlays in screen
recordings**.

Turn off Stage Manager before using Tabbed. Pane assignments, remembered
desktops of disconnected displays, followed Saved Layouts and Undo history
last only for the current app session. Cross-display tab dragging remains
unavailable. Applications can refuse requested sizes.

Remembered desktops are kept in memory only and are never written to disk.
Only the new settings are saved, in BetterTile's existing configuration file.
**Show overlays in screen recordings** adds no permission and starts no
capture; it only lets BetterTile's own windows appear in a screenshot or
recording that you start.

No new permission, dependency, network endpoint, or tracking is added. The
existing signing identity, update feed and Sparkle update mechanism remain in
use. Existing beta users do not need a new Accessibility grant because of this
release.

The app remains self-signed and is not notarized. A first installation may
require **Open Anyway** in System Settings → Privacy & Security.

This release advances the internal build from 16 to 17. Sparkle uses that build
number to determine update order.

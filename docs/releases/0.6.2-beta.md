# BetterTile 0.6.2 Beta

- **New apps join the layout at once.** In Adaptive and Tabbed, the first
  window of an app that you open now moves into the layout right away. Before,
  it could stay at its opening size for up to about 10 seconds. This also
  applies when the app shows its first window a few seconds after it opens.

BetterTile still runs only on Apple silicon Macs and requires macOS 26.

An app that opens hidden, or opens as a menu bar app and later becomes a
regular app with windows, can still have its first window placed late.

A second **+** request for an app that is still running is refused for up to
30 seconds after the earlier request. After you take a window to another
desktop and come back, the other Adaptive windows fill its space about 2
seconds later. While displays change, and after wake or unlock, new and closed
windows wait up to about 5 seconds for the layout to update. If you move a
floating Tabbed window to another desktop, each return from sleep, lock or the
screen saver waits the full 5 seconds until that window comes back or closes;
the layout does not change. If you change only the macOS icon style, the menu
bar Saved Layouts picker can show the old icons until BetterTile restarts.
Capture tools can differ in how they honor **Show overlays in screen
recordings**.

Turn off Stage Manager before using Tabbed. Pane assignments, remembered
desktops of disconnected displays, followed Saved Layouts and Undo history
last only for the current app session. Cross-display tab dragging remains
unavailable. Applications can refuse requested sizes.

No permission, dependency, network endpoint, or tracking is added or changed.
The existing signing identity, update feed and Sparkle update mechanism remain
in use. Existing beta users do not need a new Accessibility grant because of
this release.

The app remains self-signed and is not notarized. A first installation may
require **Open Anyway** in System Settings → Privacy & Security.

This release advances the internal build from 17 to 18. Sparkle uses that build
number to determine update order.
